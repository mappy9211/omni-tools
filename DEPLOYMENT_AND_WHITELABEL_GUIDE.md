## 1. Architecture Overview

- **Application Type**: 100% Client-Side Single Page Application (SPA) built with React 18, Vite & TypeScript.
- **WASM / Web Workers**: Uses WebAssembly & client workers for browser-based tasks (FFmpeg, ONNX, Tesseract, PDF generation).
- **Server Role**: Nginx serves compiled static files from the `/dist` directory.
- **Node.js**: Version 20+ LTS is required during build/deployment on the server.

## 2. Ploi.io Setup & Deployment

### Step 1: Server Requirements
1. In your Ploi.io dashboard, go to **Servers** → **[Your Server]**.
2. Go to the **Node.js** tab and ensure **Node.js v20.x or v22.x (LTS)** and **npm** are installed.

### Step 2: Site Creation
1. Go to **Sites** → **Add Site**.
2. Configure:
   - **Domain**: e.g., `tools.sysophost.com`
   - **Project Type**: `Generic / HTML` (or `Static`)
   - **Web directory**: `/dist` (Ploi root: `/home/{user}/{domain}/dist`)
3. Click **Create Site**.

### Step 3: Connect Git Repository
1. In the site dashboard, go to **Repository**.
2. Select your Git provider and repository (e.g. `mappy9211/omni-tools`).
3. Set the deployed branch to `whitelabel` (or `main`).
4. Click **Install repository**.

### Step 4: Configure Deployment Script
In the site's **Deploy** tab, set the deployment script to:

```bash
cd /home/tools-tovhp/tools.sysophost.com

# Pull latest commits
git pull origin {branch}

# Install dependencies cleanly
npm ci

# Build production assets into /dist
npm run build
```

*(Optional: Enable **Quick Deploy** so git pushes automatically trigger a rebuild).*

### Step 5: Environment Variables (Branding)
In Ploi site dashboard → **Environment**, add your `.env` variables:

```env
VITE_APP_NAME="Sysop Tools"
VITE_APP_DESCRIPTION="Fast and privacy-first online tools for daily tasks."
VITE_SHOW_DISCORD="false"
VITE_SHOW_GITHUB="false"
VITE_SHOW_HIRE_ME="false"
VITE_SHOW_VERSION_HASH="false"
VITE_DEFAULT_OUTPUT_PREFIX="output"
```

## 3. Nginx Configuration

In Ploi, go to **Manage** → **Edit Nginx configuration**. Replace with the following production configuration:

```nginx
# Ploi Webserver Configuration, do not remove!
include /etc/nginx/ploi/tools.sysophost.com/before/*;

server {
    listen 80;
    listen [::]:80;

    root /home/tools-tovhp/tools.sysophost.com/dist;
    server_name tools.sysophost.com;

    include /etc/nginx/ssl/tools.sysophost.com;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ecdh_curve X25519:prime256v1:secp384r1;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384:DHE-RSA-CHACHA20-POLY1305;
    ssl_prefer_server_ciphers off;
    ssl_dhparam /etc/nginx/dhparams.pem;

    index index.html;

    # Load standard MIME types (HTML, CSS, JS, Images, WASM)
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-XSS-Protection "1; mode=block";
    add_header X-Content-Type-Options "nosniff";

    charset utf-8;

    # Enable Gzip compression
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_proxied expired no-cache no-store private auth;
    gzip_types text/plain text/css text/xml text/javascript application/x-javascript application/javascript application/xml application/json application/wasm image/svg+xml;

    # Ploi Configuration, do not remove!
    include /etc/nginx/ploi/tools.sysophost.com/server/*;

    # SPA Fallback - route all paths to index.html for React Router
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Cache immutable static assets (JS/CSS chunks generated by Vite)
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, max-age=31536000, immutable";
        access_log off;
    }

    # Never cache index.html so updates are immediately available
    location = /index.html {
        expires -1;
        add_header Cache-Control "no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0";
    }

    access_log off;
    error_log  /var/log/nginx/tools.sysophost.com-error.log error;

    location = /favicon.ico { access_log off; log_not_found off; }
    location = /robots.txt  { try_files $uri =404; access_log off; log_not_found off; }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}

# Ploi Webserver Configuration, do not remove!
include /etc/nginx/ploi/tools.sysophost.com/after/*;
```

## 4. White-Label Customization

All branding elements are decoupled into `src/config/branding.ts` and driven by environment variables:

| Variable | Description | Default |
|---|---|---|
| `VITE_APP_NAME` | Brand title displayed in Navbar, Hero, Titles & Manifest | `"Tools"` |
| `VITE_APP_DESCRIPTION` | Subtitle / description displayed in Hero | Generic toolkit text |
| `VITE_SHOW_DISCORD` | Show/hide Discord invite button in Navbar | `false` |
| `VITE_SHOW_GITHUB` | Show/hide GitHub star button in Navbar | `false` |
| `VITE_SHOW_HIRE_ME` | Show/hide author Hire Me button in Navbar | `false` |
| `VITE_SHOW_VERSION_HASH`| Show/hide version and commit hash in Navbar | `false` |
| `VITE_DEFAULT_OUTPUT_PREFIX` | Prefix for downloaded files (e.g. `output.txt`) | `"output"` |

### Replacing Logos & Favicons
To replace the brand imagery, simply overwrite the following files:
- **Light Theme Logo**: `src/assets/logo.png`
- **Dark Theme Logo**: `src/assets/logo-white.png`
- **Favicons**:
  - `public/favicon.ico`
  - `public/favicon.svg`
  - `public/favicon-96x96.png`
  - `public/apple-touch-icon.png`

## 5. Upstream Update Protection & Sync Strategy

### How Your Changes Are Protected
1. **Decoupled Architecture**: All branding logic is centralized in `src/config/branding.ts`. Tool additions and bug fixes from the original creator in `src/pages/tools/...` or other services will not interfere with this file.
2. **Branch Isolation**: The original upstream changes stay on `main`, while your white-label customizations reside on the `whitelabel` branch.

### Option A: Fully Automated via GitHub Action (Recommended)
A pre-configured GitHub Action workflow is included in `.github/workflows/sync-upstream.yml`.

- **Automatic Schedule**: Runs automatically every week (Monday at midnight UTC).
- **Manual Trigger**: You can run it anytime on demand by going to your GitHub repository → **Actions** → **Sync Upstream & Rebase Whitelabel** → **Run workflow**.
- **Ploi Auto-Deploy**: When the action pushes the rebased `whitelabel` branch, Ploi receives the webhook and automatically deploys the updated build!

### Option B: Local Helper Script
If you prefer triggering syncs from your terminal:

```bash
bash scripts/sync-upstream.sh
```

### Option C: Manual Git Commands

```bash
# 1. Fetch upstream commits
git remote add upstream https://github.com/iib0011/omni-tools.git || true
git fetch upstream

# 2. Update your main branch
git checkout main
git pull upstream main
git push origin main

# 3. Rebase your white-label branch
git checkout whitelabel
git rebase main

# 4. Push updated whitelabel branch (triggers Ploi deployment)
git push origin whitelabel --force-with-lease
```

## 6. Automated CI/CD vs Ploi Deploy Script

### ⚠️ Why `scripts/sync-upstream.sh` should NOT be placed in the Ploi Deploy Script:

1. **Permission Denied on Git Push**: Ploi servers use read-only SSH deploy keys by default. Attempting `git push origin` inside the deployment script will fail.
2. **Production Downtime on Rebase Conflicts**: If upstream makes a conflicting change, a rebase inside the live deployment runner will pause in a detached HEAD state and fail the deployment, leaving the site broken.
3. **Deployment Runner Integrity**: Ploi expects the checked-out working tree to stay on `{branch}`. Switching branches during deployment confuses the deploy runner.

### ✅ Recommended Division of Responsibilities:
- **Upstream Sync & Rebase**: Executed by **GitHub Actions** (`.github/workflows/sync-upstream.yml`) or locally on your machine.
- **Ploi Deploy Script**: Strictly handles **pulling the latest pre-tested code and building assets**:
  ```bash
  cd /home/tools-tovhp/tools.sysophost.com
  git pull origin {branch}
  npm ci
  npm run build
  ```
